# Kainbu review and remediation — 12 September 2026

The review began at `7b6921d` and was integrated with upstream `41ec38d` before release. It identified authorization bypasses, data loss, and broken dashboard statistics across the browser, Hono, and directly reachable PocketBase API. Upstream fixes and routing changes are preserved.

## Findings addressed

| #   | Finding                                                                          | Remediation                                                                                                                                                                                                                               |
| --- | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | Any signed-in user could read or overwrite provider secrets and global settings. | All `app_settings` record rules are server-only.                                                                                                                                                                                          |
| 2   | An outsider could create their own membership in a known private project.        | All membership writes stay server-only; project creation bootstraps ownership and joining uses validated invitations.                                                                                                                     |
| 3   | Members could change project ownership or enable public sharing.                 | Ownership and identity fields are immutable; sharing changes require the owner.                                                                                                                                                           |
| 4   | A user could grant themselves admin privileges once the missing fields existed.  | Privileged flags are guarded on account creation and update, in both migrations and runtime rule repair.                                                                                                                                  |
| 5   | Claiming an unverified allowlisted email granted admin access.                   | Email-based admin access and promotion require verification. Public signup never sets `verified`.                                                                                                                                         |
| 6   | Disabling signup in Hono did not prevent direct PocketBase signup.               | A PocketBase account-creation hook enforces the signup policy.                                                                                                                                                                            |
| 7   | Disabled accounts retained direct API and personal-token access.                 | Authentication, collection rules, token resolution, and custom mutation handlers check disabled status.                                                                                                                                   |
| 8   | Task and page attachment URLs allowed anonymous downloads.                       | Files are protected and downloads request a short-lived file token.                                                                                                                                                                       |
| 9   | An untrusted page ID could escape the AI temporary workspace.                    | Temporary directories and page filenames are generated independently of user-controlled IDs.                                                                                                                                              |
| 10  | Exception-based field detection silently skipped migrations.                     | An additive migration repairs missing fields; application settings validate schema rather than altering it at request time.                                                                                                               |
| 11  | Board deletion left tasks and columns that could appear on a surviving board.    | Required board relations cascade deletes; readers no longer guess a board for orphan records.                                                                                                                                             |
| 12  | Column deletion did not remove tasks.                                            | Transactional deletion hooks remove tasks and their attachments/comments.                                                                                                                                                                 |
| 13  | Full-row task writes overwrote unrelated concurrent edits.                       | One transaction applies changed fields against the original values; independent edits merge and same-field conflicts return 409.                                                                                                          |
| 14  | Scratchpad revision checks accepted concurrent stale writes.                     | Compare-and-update now executes inside a database transaction.                                                                                                                                                                            |
| 15  | Failed membership creation left invitations permanently accepted.                | Invitation status and membership commit together. Retries are idempotent and cannot re-enroll a subsequently removed member.                                                                                                              |
| 16  | Pending edits were lost on reload and failures did not retry.                    | Serializable board/page queues retain original bases, serialize writes, recover before remote merging, and retry transient failures on reconnect/focus and every 30 seconds. Conflicts retain drafts and offer backup plus server reload. |
| 17  | Projected user records produced empty or internal-host avatar URLs.              | Avatar helpers retain collection identity and use the public PocketBase origin.                                                                                                                                                           |

Additional fixes accept authoritative remote board/page state when no local mutation is pending, including resets to default preferences and clients with clocks running ahead. CORS now permits token revocation via DELETE; nginx permits a 20 MiB attachment plus multipart metadata. Backup tests use checked-in synthetic data instead of a developer's download directory.

The upstream integration also fixes private chat/user-state access, page attachment exposure, and soft-leave authorization in both PocketBase and privileged server readers. The active-membership rule now matches a single active row, so another member leaving cannot lock everyone out. Soft-deleted tasks remain excluded from dashboard, public-share and AI views; explicit local deletion state preserves undo and prevents stale edits from resurrecting tasks. The dedicated dashboard route overrides remembered board state on desktop and mobile. Release smoke scripts now use server project creation and clean up their disposable records.

## Dashboard definitions

- Counts include every board in every accessible project, without counting the active-board alias twice.
- **Open tasks:** non-deleted tasks whose `checked` flag is false.
- **Overdue:** open tasks with a due time before now.
- **Due today:** open tasks due on the local calendar date, including those already overdue today.
- **Completed in 7 days:** currently completed tasks with a recorded completion time within the rolling seven-day window.
- Pinned shared projects remain included in the shared-project count. Timed-task links and clear actions address the correct board.
- Missing historical timestamps remain unknown. Newly created/updated records receive real PocketBase timestamps. Reopened tasks and future timestamps do not inflate completion/activity statistics.
- Recent changes are derived from the latest stored task/member/invitation state. They are not an exhaustive audit log, so the misleading action-count and week-over-week activity cards were removed.

## Validation

On Node 22.23.2 and the production-pinned PocketBase 0.38.2:

- Frontend and server typechecks pass with zero errors and warnings.
- 224 unit tests pass, with six infrastructure-dependent tests skipped.
- 20 real PocketBase security/integrity tests pass on fresh and upgraded databases. Coverage includes concurrent edits, atomic rollback, invitation failure/retry, file access, disabled accounts, migration preservation, path traversal, and avatar URLs.
- 54 native-stack HTTP/integration tests pass. Authenticated AI/provider tests remain skipped without disposable provider configuration.
- Production web build and CLI build pass.
- Browser verification covers dashboard counts across two boards, timed-task navigation, an offline edit followed by reload and successful retry, and desktop/mobile layouts.

The Docker engine could not start because of a stale Docker Desktop inference socket. Automatic approval review blocked its removal. Native HTTP tests exercise the application and Vite proxies; Docker images and nginx runtime behavior remain unverified locally. Repository-wide lint also has a substantial pre-existing failure baseline; it is not a passing gate for this change.

## Remaining architectural work

1. Narrow realtime refreshes: presence heartbeats currently trigger full workspace reads, including task/page/chat payloads. This remains a scaling risk, not a measured load-test result.
2. Continue extracting state management from the large `WorkspaceShell.svelte` component. The board/page queue is now independently tested, but chat/settings and some metadata mutations still use separate synchronization paths.
3. Add a durable event ledger if historical throughput, deletion history, or per-person activity is required. Snapshot timestamps cannot reconstruct that history.
4. Reduce duplicated read/mapping code and establish a clean lint/CI baseline.

The migration preserves existing data. It cannot reconstruct lost board associations, missing historical timestamps, or distinguish a previously broken accepted invitation from an intentionally removed member. Those cases need explicit recovery from a backup or a new invitation, rather than automatic access grants.
