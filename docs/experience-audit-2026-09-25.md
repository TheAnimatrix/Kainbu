# Kainbu experience audit — 2026-09-25

Scope: current checkout, self-hosted Docker setup, browser and Android configuration, authentication, collaboration, AI proposals, recovery, and release checks. This is a prioritized issue inventory, not a claim that every path was exercised in a browser. P0 means a plausible unauthorized-access or major data-loss path; P1 means a serious recurring workflow failure; P2 means material usability, reliability, or operating friction.

## P0

1. **Unverified accounts can accept email-address invitations.** Signup creates users with `verified: false` and only requires verification when mail is configured (`server/admin.ts:234-315`). The PocketBase auth rule checks only `disabled` (`pocketbase/pb_migrations/1730000038_security_integrity.js:29`), and the API's JWT resolver does not check `verified` (`server/pocketbase.ts:269-303`). Invite creation links an existing account by email (`server/workspace.ts:249-261`, `:449-500`); acceptance checks the same email or linked user ID without verifying address ownership (`pocketbase/pb_hooks/workspace.js:205-243`). The passing integration test at `tests/pocketbase.integration.test.ts:314-342` exercises acceptance by an unverified account. A person who registers another person's address before the intended recipient can acquire an invitation to that address. The browser's verification gate is insufficient because an authenticated client can call the API directly. Require verified ownership before linking or accepting email invitations; when mail is unavailable, use an explicit invite secret or administrator provisioned identity.

2. **An omitted environment variable creates a known PocketBase superuser.** Compose defaults `POCKETBASE_ADMIN_PASSWORD` to `kainbu-admin-change-me` for both PocketBase and API (`docker-compose.yml:10,31`), and the entrypoint upserts that account on every start (`docker/pocketbase-entrypoint.sh:7-9`). The example environment repeats the same password (`.env.example:8`). The README tells operators to change it, but deployment still succeeds when they do not. Fail startup when no strong secret is supplied; avoid resetting a superuser to a template value on restart.

## P1

3. **AI proposal previews can erase card links while advertising zero changes.** `normalizeTask` omits `linkedTaskIds` (`server/workspace-ai/sync.ts:167-198`), while proposal operations are derived from that normalized board and the preview is saved as a whole board (`server/workspace-ai/sync.ts:1037-1059`, `src/lib/components/WorkspaceShell.svelte:4149-4171`). A disposable PocketBase diagnostic reproduced an unedited AI proposal with `ops: []` that cleared persisted links. Make the AI board codec lossless and reject any preview that differs from applying its reviewed operations.

4. **A successful sync can store a card in a deleted column, making it invisible.** The transactional board hook checks project and board but never validates an upserted task's text `column_id` against a live column (`pocketbase/pb_hooks/workspace.js:84-170`). The normal loader groups tasks by existing column IDs (`src/lib/kainbu/loadWorkspaceFromRemote.ts:103-125`). A real-database reproduction deleted a column between read and write: the sync returned success and the new card disappeared from the board. Validate parent existence inside the transaction after applying the batch.

5. **Board Undo can erase a collaborator's later changes.** History stores full board snapshots and Undo applies an older snapshot (`src/lib/components/WorkspaceShell.svelte:3853-3875`); mutation derivation interprets every difference against the current board as intentional (`src/lib/kainbu/boardSyncCore.ts:123-223`). A diagnostic reproduced Undo of a title edit clearing another user's description and deleting their new card. Store guarded inverse operations for the local action instead of replacing the whole board.

6. **An old read can replace a newer acknowledged save.** After a write succeeds, the sync queue removes its pending entry (`src/lib/kainbu/syncQueue.ts:37-53`); board merge then accepts the remote board whenever no edit is pending (`src/lib/kainbu/projectStructure.ts:187-213`). Refresh carries no server revision fence and returns the current in-flight request (`src/lib/components/WorkspaceShell.svelte:2311-2353`). A response-order diagnostic reproduced a saved title reverting locally after a delayed old snapshot. Add monotonic board revisions and reject snapshots older than the last acknowledged write.

7. **The repository's self-hosted stack has no automated backup or recovery job.** Compose persists PocketBase data in one local named volume (`docker-compose.yml:11-13,54-55`) and defines no scheduled backup, off-host copy, or restore check. The only app-facing “Backup” action is the incomplete content export described below (`src/lib/components/ProjectSheet.svelte:299-313`). Operators without a separate backup system can lose accounts, files, comments, and workspace history with the host volume. Provide a documented, scheduled PocketBase data-and-files backup with a tested restore path.

8. **The advertised backup omits significant workspace data.** The v3 export writes only project names, boards, and pages (`src/lib/kainbu/backup.ts:420-438`). `stripTaskForBackup` discards task links and assignees (`:139-145`), and the payload has no members, comments, task/page assets, AI history, or project background. Restoring such a file cannot reconstruct the workspace users thought they saved. Label the export as content-only until a round-trip verified full backup exists; add a server/database backup path for files and relations.

9. **Restore can leave partial duplicate projects after failure.** The UI creates imported projects sequentially (`src/lib/components/WorkspaceShell.svelte:5314-5342`), then validates only that project and board counts match (`:5344-5362`). The catch path records an error but does not roll back already created projects (`:5386-5391`). Retrying can create another copy. Use a transactional import job or idempotent restore ID, and verify all boards, cards, pages, and attachments before claiming success.

10. **Deleting a column permanently removes task details that task Undo cannot restore.** Individual task deletion uses tombstones (`pocketbase/pb_hooks/workspace.js:158-168`), but deleting a column calls a hard-delete hook that deletes child tasks and their assets/comments (`pocketbase/pb_hooks/workspace.js:246-282`). A user's Undo snapshot cannot recreate those child records. Give columns and dependent content a recoverable trash lifecycle, or explicitly warn and require permanent deletion.

11. **Persisted AI proposals can be attached to the wrong board.** `AiKanbanProposal.boardId` remains optional (`src/lib/kainbu/types.ts:614-630`), and restoring a proposal falls back to the currently active board (`src/lib/kainbu/aiProposals.ts:140-147`). The disposable diagnostic confirmed the same stored proposal changes target as navigation changes. Require immutable project/board identity on creation, persistence, review, and apply; reject legacy proposals without a resolvable target.

12. **Unchanged boards can be flagged as stale to AI.** The browser mapper normalizes PocketBase's zero due timestamps to empty (`src/lib/kainbu/pbRecords.ts:150-155`), while the AI mapper retains zero (`server/workspace-ai/sync.ts:445-448`). The loaders also use different default column widths and tie-break ordering (`src/lib/kainbu/loadWorkspaceFromRemote.ts:28,102-125`, `server/workspace-ai/sync.ts:36,320-339`). A real-database diagnostic reproduced a fingerprint mismatch without any edit. Share one record-to-domain mapping and canonicalization contract.

## P2

13. **Two offline tabs can overwrite each other's recovery state.** A single localStorage key holds each account's entire workspace snapshot (`src/lib/kainbu/localSnapshot.ts:8-12,75-95`), and the in-memory sync queue has no durable operation IDs or cross-tab coordination (`src/lib/kainbu/syncQueue.ts:17-58`). This is a static risk, not browser-reproduced in this audit. Persist individual pending operations in a transactional outbox and coordinate writers across tabs.

14. **Every realtime event reloads the whole workspace.** The client subscribes to nine broad collections (`src/lib/kainbu/persistence.ts:1128-1161`); any event schedules `fetchWorkspace`, which retrieves all accessible projects, boards, pages, columns, tasks, user state, and AI sessions (`src/lib/components/WorkspaceShell.svelte:2311-2353`, `src/lib/kainbu/loadWorkspaceFromRemote.ts:190-304`). Presence heartbeats occur every 30 seconds (`src/lib/kainbu/boardPresence.ts:3-4`, `src/lib/components/WorkspaceShell.svelte:1993-1995`). As a workspace grows, a small edit or presence ping can cause large repeated reads and visible refresh churn. Scope invalidation and queries by project/board and data type.

15. **Workspace reads are not one consistent snapshot.** The snapshot loader issues independent PocketBase list requests in parallel (`src/lib/kainbu/loadWorkspaceFromRemote.ts:246-304`) with no shared revision or transaction. A concurrent column move/delete can produce a response assembled from different database moments. Return a transactionally consistent server snapshot or retry when a board revision changes during the read.

16. **AI review mislabels moves and hides link changes.** `computeKanbanDiff` compares tasks globally but checks removal per source column, so a pure move appears removed at the source and unchanged at the destination (`src/lib/kainbu/diff.ts:178-238`). `areKanbanTasksEqualForDiff` does not compare `linkedTaskIds` (`:111-136`). The current unit tests assert these behaviors (`tests/kanbanDiff.test.ts:12-19,93-160`). Review should derive its text and safety counts from the exact operations to be applied.

17. **The documented non-Docker development flow starts with broken auth.** README says to copy `.env.example` to `.env.local` and run `npm run dev:full` (`README.md:62-71`), while `VITE_POCKETBASE_URL` is commented out in the template (`.env.example:3`). The browser then uses same-origin `/pb` (`src/lib/pocketbaseClient.ts:17-27`), but Vite proxies only `/api` and `/health` (`vite.config.ts:25-35`). Auth requests therefore hit the Vite app instead of PocketBase. Proxy `/pb` in Vite or set the local PB URL in the documented command.

18. **The Android build is coupled to one hosted server.** Native clients default both API and PocketBase to `https://kainbu.avarnic.com` (`src/lib/kainbu/api.ts:8-17`, `src/lib/pocketbaseClient.ts:20-27`), with no server picker in the app. A self-hoster's APK connects to the official host unless rebuilt with paired overrides. Make server selection a visible setup step and store it per installation.

19. **Release checks are advisory rather than enforced.** The repo has no GitHub Actions workflow; the release skill states that checks are run manually before push (`.cursor/skills/kainbu-release/SKILL.md:1-16,70-81`). The unfiltered `npx vitest run` also includes deploy/Docker tests that fail when no stack is running. This makes it easy to ship the P0/P1 regressions above despite passing unit tests. Add a deterministic CI unit/typecheck job and an integration job with a disposable PocketBase/compose stack.
